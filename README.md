# ConMarn

**基于端侧大模型的本地优先多智能体协同与跨设备执行系统。**

系统以 Android 手机为宿主：对话推理、语音识别与合成、三维形象渲染、记忆存储均在本机完成，断网可用；通过统一的能力契约接入个人电脑等外部设备；第三方模型接口作为可选兜底，默认关闭。

> **许可：** 本项目以 Apache License 2.0 发布，完整条款见 [LICENSE](LICENSE)。所依赖第三方组件的许可与使用边界见 [THIRD_PARTY.md](THIRD_PARTY.md)，架构说明见 [ARCHITECTURE.md](ARCHITECTURE.md)。

> **使用范围：** 接入电脑后，手机可控制鼠标、屏幕、摄像头、麦克风并双向传输文件，权限范围较大。仅在可信局域网中启用；配对种子、二维码与恢复码等同密钥，不得截图或转发。

## 一、系统定位

系统按端、边、云三个节点组织。

| 节点 | 承担 | 实现位置 |
|---|---|---|
| 端 | 判断：对话推理、语音处理、形象渲染、记忆与任务调度 | Android 手机，本仓库 `app/` |
| 边 | 执行：受控设备的统一接入层 | 能力契约与独立接入进程，本仓库 `pc-server/` |
| 云 | 兜底：可选的第三方模型接口 | 由使用者自行填入密钥，未填即不启用 |

端做判断，边做执行，云做兜底。断开边，端仍可正常对话；断开云，端仍可离线运行。

边节点的定义是接口，而非某一台具体设备：设备自述能力清单，宿主按清单派发任务，任务必须回执。契约只规定通信方式，不规定设备类型、操作系统与厂商，个人电脑是第一个接入的节点。

## 三、技术实现

| 层 | 选型 | 理由 |
|---|---|---|
| 推理框架 | llama.cpp，针对目标芯片自编原生库 | 端侧可运行量化模型；自编译后吞吐提升约 2.5 倍【实测，同机型对比】 |
| 模型 | 端侧量化语言模型，视觉模型按需加载 | 内存受限设备可分级启用 |
| 语音 | 唤醒、识别、断句、合成四段全部本地运行 | 全链路不依赖网络 |
| 形象 | WebGL 渲染，运行于 WebView | 与原生层双向通信，无专用硬件成本 |
| 外设 | 能力契约：能力自述、强制回执、指令签名 | 新增设备不修改宿主 |
| 云端 | 第三方大模型接口，使用者自填密钥 | 本地超时兜底；未填即不启用 |

**端侧前缀快照。** 智能体的固定前缀（系统提示词与工具定义）在每轮会话中重复送入模型，端侧算力下的重复计算代价很高。本项目将该前缀的计算结果持久化为磁盘快照，冷启动时直接恢复。实测：约 4,889 词的固定前缀首次计算耗时 685,325 毫秒，快照恢复耗时 434 毫秒，快照体积 764.6 MB【两项均为实测，目标机型为日常使用的中端安卓手机】。

**语音半双工控制。** 语音对话不同于听写，若在合成播放期间持续采集，会形成自激。本项目将半双工闸挂在语音合成的完成回调上，并对「用户说完后等待动作」配置硬超时，避免系统在收不到回调时挂死。

## 四、数据边界

| 级别 | 内容 | 处理方式 |
|---|---|---|
| L1 禁止出机 | 屏幕截图、原始音频、配对种子与设备凭据 | 不出手机；音频解码后即丢弃 |
| L2 本机持久 | 对话记忆、经验库、资料库、任务档案 | 仅存本机文件 |
| L3 可出机 | 使用者显式发送的文本、经自填密钥调用的第三方模型请求 | 需使用者授权 |

数据边界由架构决定，不依赖隐私政策承诺。云端兜底为总开关：关闭后，天气请求、网络检索与云端工具一并停止，截图在任何情况下都不上传。

## 五、安全机制

| 层 | 机制 |
|---|---|
| 电脑端登录 PIN | 打开电脑端界面前需输入 6 位 PIN，首次运行时自行设置 |
| 动态配对码 | 手机每次连接时，电脑显示 6 位随机码 |
| TOTP 动态码 | 配对码通过后，双方以同一密钥与当前时间各自计算 6 位动态码并自动校验 |
| 带外传递种子 | 首次配对密钥以二维码从电脑传至手机 |
| 一次性恢复码 | 设备丢失后凭首次配对时显示的 8 位码重新配对，使用一次即作废 |
| 免码续连 | resume token 为 128 位随机值，加密存储并绑定手机锁屏，锁屏状态下不可用 |
| 防暴力破解 | 连续 3 次动态码错误即锁定，锁定时长按指数递增 |
| 指令签名 | 每条控制指令携带 HMAC-SHA256 签名与递增序号，防止伪造与重放 |
| 本地加密 | 密钥与恢复码以 Windows DPAPI 加密存储，绑定当前系统账户 |
| 风险分级 | 指令按风险等级分为三档，高风险操作需二次确认；涉及支付与身份的操作在确认后再验证一次生物识别 |

## 七、安装与运行

### 手机端

- 发布包见 [官网](https://imxia-chan.github.io/ConMarn.AI/) 与 Releases 页，当前版本 3.1.1（versionCode 32），发布包约 73 MB。
- 自行构建：用 Android Studio 打开工程根目录，或执行 `gradlew assembleRelease`。

### 电脑端

- 发布形态为单一可执行程序，启动后按提示设置 6 位登录 PIN。
- 从源码运行需 Python 3，依赖 `segno` 与 `pillow`：

  ```bash
  pip install segno pillow
  python pc-server/server.py
  ```

  未安装 `segno` 时二维码不可用，可改为手工抄录 32 位种子；未安装 `pillow` 时屏幕镜像不可用，其余功能正常。
- 默认端口 9527，界面顶部显示本机地址，手机端填入该地址即可连接。
- 建议以管理员身份运行。否则手机无法控制以管理员权限打开的窗口，这是 Windows 的权限隔离机制，不是程序缺陷。

### 配对流程

1. 手机与电脑连接同一局域网，在手机端点「扫描」自动发现电脑，也可手动输入地址。
2. 输入电脑上显示的 6 位配对码。
3. 首次配对时扫描电脑显示的二维码，并记录 8 位恢复码。
4. 此后每次连接只需配对码，动态码自动校验；掉线或重启后自动免码续连。

## 九、常见问题

- **无法连接：** 确认手机与电脑处于同一局域网，并已在防火墙中放行对应程序。
- **扫描不到电脑：** 自动发现依赖局域网广播，路由器的访客网络、AP 隔离或防火墙规则会拦截，此时手动输入地址即可。
- **动态码校验失败：** 手机与电脑的时间不同步，请双方均开启自动校时。
- **手机重装后无法连接：** 使用首次配对时记录的 8 位恢复码重新配对。
- **需要彻底重新配对：** 删除电脑端 `pc-server/secret.json` 后重新连接。
